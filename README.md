## 这是什么

这是一个**个人整理的大模型知识库**，目标不是"追新闻"，而是回答三个问题：

1. **它是怎么走到今天的？** —— 为什么是 Transformer，为什么是 RLHF，为什么突然开始"推理"，为什么又转向 Agent。
2. **它现在长什么样？** —— 有哪些方向、哪些技术、哪些工具，分别处在什么成熟度。
3. **我该怎么用？** —— 选型、查漏、写方案、做培训时，能快速找到坐标。

内容以**公开论文、官方发布、行业复盘**为依据整理；2025–2026 年的版本迭代极快，相关条目均标注"以官方为准"。

## 一、《大模型发展全过程》

**定位**：一条主线串起 83 年，重点讲"**为什么变**"，而不是"**变了什么**"。

### 内容结构

| 部分 | 内容 |
|---|---|
| 0 | 全局阶段表：四次范式切换（预训练 → 对齐 → 推理 → 智能体） |
| 1 | 前史 1943–2016：神经元、反向传播、LSTM、word2vec、seq2seq、Attention、AlphaGo |
| 2 | 2017 Transformer：四个部件与它为什么赢 |
| 3 | 2018–2019 预训练范式：GPT 与 BERT 的分叉、T5/RoBERTa/XLNet |
| 4 | 2020–2021 规模定律：GPT-3、Scaling Laws、Chinchilla、ViT/CLIP/Codex、MoE |
| 5 | 2022 对齐与破圈：InstructGPT、RLHF、ChatGPT、扩散模型、Constitutional AI |
| 6 | 2023 军备竞赛：GPT-4、三足鼎立、Llama 开源、RAG、Agent 雏形 |
| 7 | 2024 多模态与推理：GPT-4o、长上下文、Llama 3.1、o1、MCP、DeepSeek-V3 |
| 8 | 2025 推理普及与 Agent 元年：R1、GPT-5、Claude 4.5、Gemini 3、Coding Agent |
| 9 | 2026 前沿竞速：GPT-5.x/6、Claude 5、DeepSeek V4、Kimi K3、世界模型 |
| 10 | 横向五条技术线：架构 / 后训练 / 推理 / 数据 / 算力与产品 |
| 11 | **七条规律**：范式切换、预训练定天花板、成本崩塌、基准寿命、开源滞后、可验证性、任务碎片化 |
| 12–13 | 争议清单与未来 2–3 年看点 |
| 附录 | 总时间线速查、15 篇必读论文、术语表 |

### 它的价值

- **因果链而非年表**：每个节点都回答"上一阶段的瓶颈是什么、这一阶段用什么杠杆解决"。
- **可复用的判断框架**：七条规律可以直接拿来判断新模型、新赛道、新商业故事。
- **写作素材库**：做分享、写方案、写周报的背景章节，可以直接摘。

### 适合谁

需要**建立全局感**的人：产品经理、投资人、技术管理者、刚入行的工程师、需要给团队做科普的人。

## 二、《大模型全景图谱》

**定位**：一张横向地图，重点解决"**有没有漏**"和"**这东西属于哪一层**"。

### 内容结构

| 部分 | 内容 |
|---|---|
| 0 | 八层技术栈总图（L0 基础设施 → L7 治理评估）+ 三条读图要点 |
| Part I | **阶段 × 新生方向/技术/工具** 对照表：每个时代长出了什么 |
| Part II | **19 条赛道**：语言、数学、代码、多模态理解/生成、语音、Agent、多智能体、RAG、长上下文、世界模型、AI4Science、搜索推荐、端侧、垂直行业、评测、安全、数据、基础设施 |
| Part III | **L0–L8 逐层拆解**：芯片/并行/框架 → 数据 → 架构 → 训练对齐 → 推理部署 → 能力扩展 → 应用形态 → 评测治理 → 产业生态 |
| Part IV | **效率技术全景**：量化、蒸馏、剪枝、广义压缩、投机解码、训练效率 + 取舍矩阵 |
| Part V | **技能、记忆与持续学习**：Skill 的定义与生态、Skill/Tool/MCP/Memory 的边界、记忆体系、灾难性遗忘 |
| Part VI | 成熟度矩阵：每条赛道的瓶颈与两年判断 |
| Part VII | 四条学习路径（产品 / 工程 / 算法 / 研究） |
| 附录 A | 31 条术语速查 |
| 附录 B | 28 项"容易漏掉的技术"补遗清单 |

### 它的价值

- **查漏**：附录 B 专治"我是不是漏了什么"，从长度外推到知识编辑、从水印到隐私计算。
- **定位**：任何新技术都能被放进八层栈的某一层，避免"把工具当方向、把方向当趋势"。
- **选型**：效率技术的取舍矩阵（压缩比 / 精度损失 / 工程复杂度 / 场景）可直接用于方案评审。
- **纠偏**：专门澄清了 Tool / Skill / MCP / Memory / RAG 这几个最容易被混用的概念。

### 适合谁

需要**做技术判断**的人：架构师、AI 工程师、技术选型负责人、要写竞品分析或技术规划的人。

## 五、最容易混淆的九组概念

| 概念对 | 一句话区分 |
|---|---|
| 预训练 vs 后训练 | 预训练学"世界是什么"，后训练学"该怎么回答" |
| 微调 vs 对齐 | 微调改能力，对齐全改偏好与行为 |
| 参数总量 vs 激活参数 | MoE 看激活参数（决定成本），总参数决定容量 |
| 上下文窗口 vs 有效上下文 | 标称 1M ≠ 真的能用 1M，中间会遗忘 |
| RAG vs 长上下文 | RAG 是"按需查"，长上下文是"全带上"，趋势是融合 |
| Agent vs 工作流 | 工作流是人画好的图，Agent 是模型自己决定下一步 |
| Tool vs Skill vs MCP | 工具是手脚，技能是方法，MCP 是插座 |
| 蒸馏 vs 量化 vs 剪枝 | 蒸馏换"学生"，量化降"精度"，剪枝删"结构" |
| 幻觉 vs 错误 | 幻觉是"自信地编"，错误是"算错了" |

## 七、使用与维护

**使用建议**

- 当作**索引**而非**教科书**：先定位到层/阶段，再决定深挖哪一块。
- 引用 2025–2026 年的模型版本前，先核对官方模型页。
- 欢迎把这两份文档当作自己笔记的骨架，按需增删。

**更新原则**

1. 只写**有公开来源**的内容；厂商自报与第三方评测分开标注。
2. 版本号跟进到"代际"，不追求每个小版本。
3. 新增内容优先补进八层栈中对应的层，保持结构稳定。

**已知局限**

- 2026 年部分条目基于公开报道整理，可能存在版本偏差。
- 工具清单是"代表性"而非"穷举"。
- 统计数字为估算，仅表示覆盖广度。
